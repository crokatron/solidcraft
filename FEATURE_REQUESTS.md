# Development fork feature requests

This backlog tracks requested improvements for the `crokatron` SolidCraft development fork. It supplements the upstream [roadmap](ROADMAP.md); it does not claim upstream commitments or release dates. Current implemented scope is recorded in [the fork changelog](FORK_CHANGELOG.md).

Updated: **2026-11-17**. **Partial** means related code exists but the complete acceptance criteria are not established. **Planned** means the requested deliverable remains open. **Research** means the format or technical approach is not yet sufficient for a reliable implementation. No item below is marked complete solely because a command or button exists.

## Request and completion workflow

1. Use a stable FR identifier when creating a fork issue. Record the problem, expected behaviour, steps and a small public-safe example; do not upload private customer designs or personal settings.
2. Add scope, acceptance criteria, dependencies and intended validation before implementation. Mark **In progress** only when an owner is actively working on it.
3. Keep related work in a focused branch/commit series and preserve upstream attribution. Link issue, commits and test evidence here when available.
4. Mark **Complete** only after the criteria are demonstrated, including failure handling and undo/save/reopen where relevant. Record known limitations rather than hiding them behind a broad feature name.
5. Add the user-visible result to the changelog. Public distribution and upstream contribution are separate actions; a local implementation does not imply an upstream merge or a qualified release.
